## 续四：真机验收带出第二批缺陷 —— 4 个 DTO 类型错误 + 图片 CDN 无回退（已推送）

承接「续三」，开始跑产品设计 §8 的真机 checklist（MuMu `127.0.0.1:16384`）。
主链路走通后，**真机立刻暴露了一族桌面单测完全看不见的缺陷**。
共同模式：DTO 字段类型与线上形态不符 → 整包解析抛异常 → 调用方 `runCatching` 吞掉 →
表现为「列表空白 / 点了没反应」而不是报错。

### 四个「整包解析失败」级 DTO 错误（v0.1.1 修）

| 字段 | 线上实际 | 原声明 | 后果 |
|---|---|---|---|
| `/setting.app_shunts` | 对象数组 `[{title,key}]` | `List<String>` | **域名四级自愈整条链路静默失效** |
| `/categories[].id` | 首条 `最新A漫` 是数字 `0`，其余字符串 | `String` | 分类列表静默变空 |
| `/chapter.data.id` | 裸数字 `646603` | `String` | **阅读器打不开任何一章** |
| `/forum.expinfo.badges` | 对象数组 `[{content,name,id}]` | `List<String>` | 评论页全空 |

修法：新增 `JmFlexibleStringSerializer`（数字/字符串都读成 String）、新增 `JmBadge` DTO。
**关键教训**：`app_shunts` / `badges` App 根本没消费，但 kotlinx 解析失败是**整包级**的 ——
一个用不到的字段类型写错会连带打挂整个接口。

### 另两个 P0（v0.1.1 / v0.1.2 修）

- **HTTP 5xx 被当业务错误不换域**：`JmClient.execute` 把非 2xx 全归为业务异常直接上抛。
  实测 `/search` 在 4 个镜像上**随机** 500（空体），同时必有镜像 200 —— 不换域 = 硬失败。
  新增 `JmClient.isRetryableHttpStatus`（5xx/429 换域，其余 4xx 上抛）。
  `tools/jm-lib.mjs` 同步修正（它此前与 App 行为不一致，会给出错误结论）。
- **图片 CDN 完全没有失败转移**：`JmImageFetcher` 只请求一个散列 host，失败即终止；
  `DomainPool.badUntil` 只服务 API 域。而 `/setting.img_host` **每次请求都可能不同**，
  各 CDN 又会被 DNS 按区域屏蔽（实测本机 `*.jmapiproxy3.cc` → `127.0.0.1`）。
  → 散列命中坏 CDN 则整本书的图永远打不开。新增图片侧健康表 `badImageUntil`
  （**与 API 的 badUntil 分开维护**，两套域名故障互不相关）+ `imageHostOrder` 逐 host 重试，
  `JmImageFetcher` 与 `DownloadManager` 都改。

### 根因治理（比修 bug 更重要）

1. **fixture 是手写的**（`"测试本子A"` / `"评论者甲"`），形状本身就是错的 —— 单测绿是假绿。
   `tools/dump-fixtures.mjs` 重写为「真实响应 + 自由文本脱敏成 `[sample:<字段名>]`」
   （评论区含导流广告与成人向文案，不宜入库；保留全部类型/结构/数组长度）。
2. **`jm-shape-probe.mjs` 发现不了「DTO 声明与线上不符」**：它的基线录的就是线上形态，
   两边永远一致。新增 **`tools/jm-dto-contract.mjs`**：解析 `JmModels.kt` 的 data class 声明，
   推导期望 JSON 类型，与线上形态基线逐字段对账，不符退出码 1。
   已用**负向控制**验证（把 `app_shunts` 改回 `List<String>` 能报错）。
   → 应进发版门禁，见 `docs/release.md` §1。
3. **kotlinx 强制转换语义是不对称的**（此前只是印象）。新增 `KotlinxCoercionSemanticsTest` 固化：
   数字→`String` **抛异常**（唯一会炸的方向）；字符串数字→`Int`/`Long` 自动转；
   字符串布尔→`Boolean` 自动转；`null`→非空字段靠 `coerceInputValues` 兜。
   推论：线上可能是数字的字段声明成 `String` 就是定时炸弹；声明成数字两种形态都能吃。
