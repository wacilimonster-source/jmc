# JM Reader · 产品设计文档

> 项目：独立禁漫阅读器（与 PiKA 哔咔阅读器拆分为两个 App）
> 代码基线参考：PiKA v1.5.51（ece5180）
> 依据：`pika/reports/jm-source-design-20260919.html`（2026-09-19 禁漫线上实测调研）+ 上级目录参考项目（JMComic-Crawler-Python / JMComic-qt / haka_comic）
> 版本：v1.0 · 2026-09-20

---

## 0. 一页纸结论

- **定位**：只做禁漫一个源的独立 Android 阅读器。**不登录即可完整使用全部读链路**（浏览 / 分类 / 搜索 / 排行 / 详情 / 阅读 / 评论只读 / 下载），这是禁漫相对哔咔的结构性优势，也是本 App 存在的理由。
- **产品原则**：① 能力说真话——源没有的功能入口直接消失；② 读优先、写谨慎——未经真实账号验证的写能力一律不进主界面；③ 阅读体验内置「图片乱序自动还原」，用户永远不该知道「scramble」这个词。
- **与 PiKA 的关系**：代码 fork 起步、产品上完全独立（独立包名、独立图标、独立更新通道、独立数据目录）。两 App 不做联动、不做跨源聚合。
- **工期**：M0–M5 约 7–9 个工作日可用可发版；登录写侧（收藏 / 签到 / 云端历史 / 发评论）卡在测试账号，账号到位前入口隐藏，不占工期承诺。

## 1. 背景与拆分动机

1. **维护割裂**：PiKA 当前是双源 App（哔咔 + 禁漫），但禁漫源六条主链路解码失败潜伏 16 天无人发现（调研报告 D1）。双源架构下「每个源都要真机回归」的成本被低估了。
2. **账号前提不同**：哔咔所有列表接口免登录一律 401（必须先登录），禁漫全部读端点免登录 200。硬塞进同一个导航框架，导致「强制登录」「我的页按源换骨架」等一堆特判（pika 里已有 6 处 `isJm` 硬编码）。
3. **节奏不同**：哔咔侧有 20 秒限流冷却、双域互切；禁漫侧限速宽松、4 镜像 + 服务端下发域名轮换。网络韧性策略完全不同，塞在一起互相牵制。
4. **拆分后各自变简单**：单源 App 不再需要源切换状态机、路由源命名空间、本地数据源前缀、按源隐藏 UI 的能力位判断——调研报告中 D4 / D5 / D6 三大 P0 缺陷在单源形态下**整体消失**而非逐个修复。

## 2. 产品定位

| 维度 | 决策 |
|---|---|
| 产品名（暂定） | **JM Reader**（禁漫阅读器）。正式名与图标待定，不占用工期 |
| 包名（暂定） | `com.jmread`（applicationId 与 namespace 一致；与 com.pika 互不覆盖安装） |

## 3. 用户与核心场景

**目标用户**：已知晓禁漫、希望有稳定移动端阅读体验的成人用户（18+）。App 首启显示年龄声明页（18+ 确认，本地记住选择，不入账）。

### 场景 1 · 装了就能看（最核心）
新用户安装 → 首启 18+ 确认 → 直接进首页浏览流，无登录墙。对比：哔咔类 App 列表接口免登录 401，必须先有账号。**这条场景决定了首页信息密度、默认排序、以及「我的」页在未登录时也有完整本地功能。**

### 场景 2 · 目标明确的找书
用户带着明确目的来：搜关键词 / 搜作者 / 看日周月排行 / 从标签墙进。四维搜索（综合 / 作品 / 作者 / 标签）各有独立结果集与真实 total。

### 场景 3 · 长阅读与沉淀
阅读器内滚页/翻页 → 退出续读（本地进度）→ 最近阅读快速回跳 → 看完标记已读 → 收进本地书架 → 下载整本离线看。

### 场景 4 · 断网 / 断服韧性
API 镜像域名失效 → 自动换下一个镜像 + 从 /setting 取新域名，用户无感；下载过的内容离线可读，且**离线看到的图必须是还原后的**。

### 场景 5 · 登录用户（P2，账号到位后）
登录 → 云端收藏同步（读侧初值回填先行）→ 每日签到 → 云端浏览历史 → 发评论。

## 4. 信息架构

### 4.1 底部导航（4 Tab）

```
┌─────────┬─────────┬─────────┬─────────┐
│  首页    │  分类    │  搜索    │  我的    │
│  home   │ category│ search  │  mine   │
└─────────┴─────────┴─────────┴─────────┘
```

- **首页**：浏览流（排序 chip：最新 / 最多观看 / 最多喜欢——只有 3 项，无「旧到新」）+ 顶部横排入口：排行榜、每周必看。
- **分类**：10 大类网格（带 total_albums 真实存量）→ 点大类进「子分类 chips + 该类浏览流」；页顶「官方标签墙」入口（43 个官方标签，4 组，来自 /categories blocks）。
- **搜索**：关键词框 + 维度 Tab（综合 / 作品 / 作者 / 标签，main_tag=0/1/2/3）+ 分类过滤 c= + 排序。结果数显示真实 total。
- **我的**：未登录 = 纯本地中心；已登录 = 增加云端区块（收藏 / 签到 / 云端历史）。

### 4.2 页面地图

```
home                首页浏览流（排序 chip + 分页）
├─ rank             排行榜（日 / 周 / 月，显示「共 N 部」）
├─ weekly           每周必看（/week 期数列表 → 某期内容流）
├─ comic/{id}       漫画详情（封面/作者/标签/章节/相关推荐/评论）
│   ├─ reader/{photoId}      阅读器（全屏）
│   ├─ comments/{albumId}    评论列表（含内嵌子评论 replys）
│   └─ author/{name}         作者/作品/标签搜索结果页（复用搜索维度）
category            分类总览（大类 + 标签墙入口）
├─ category/{slug}            单分类流（子分类 chips）
└─ tagwall → search?mainTag=3 标签流
search?keyword=&mainTag=      搜索（四维 Tab + 分类过滤）
mine                 我的
├─ bookmarks         本地书架（本地收藏）
├─ recent-reads      最近阅读（含续读卡片）
├─ downloads         下载管理（占用/速度/重试/删除）
├─ finished-reads    已读 / 读完列表
├─ login             登录（用户名+密码 → AVS 会话）
├─ cloud-favourites  云端收藏（登录后，验证通过才放开）
├─ cloud-history     云端历史（登录后，验证通过才放开）
├─ checkin           每日签到（登录后，验证通过才放开）
└─ settings          设置（域名 / 阅读 / 通用 / 日志 / 关于-更新）
```

路由只保留 `comic/{id}` 与 `reader/{photoId}` 两级内容路由——**无源命名空间**（单源 App，漫画 id 天然唯一，纯数字）。

## 5. 功能设计

### 5.1 首页 · 浏览流

| 项 | 设计 |
|---|---|
| 数据 | `/categories/filter?page&c&o&t=a`，页大小 80 |
| 排序 chip | 最新(mr) / 最多观看(mv) / 最多喜欢(tf)。**不出现「旧到新」**——服务端无升序参数，客户端倒序跨页语义是错的（实测 E4） |
| 翻页 | **硬上限 125 页**（浏览流 total 恒为 10000=125×80，第 126 页起服务器原样重发第 125 页）。滑到第 125 页显示「到底了」，不再发请求、不出现重复卡片 |
| 时间筛选 | 无。`t=` 四种取值实测返回相同，参数不存在，不渲染任何时间筛选 UI |
| 随机推荐 | 无该区块。`/random` 不存在（Not legal），`o=md` 是稳定序不是随机序——**入口消失，而非空转** |
| 卡片 | 封面（_3x4 高清优先，失败回退普通封面）+ 标题 + 作者 + 分类名 + 日期；已读角标（本地已读标记） |
| 断服 | 顶部错误条 + 「换条线路重试」按钮（触发域名轮换）；不静默转圈 |

### 5.2 分类 · 标签墙（禁漫优势位）

| 项 | 设计 |
|---|---|
| 大类 | `/categories` 10 大类，每类显示真实存量（如「同人志 34.9 万」），无封面 → chip/网格文字样式 |
| 子分类 | 每类 1~6 个 sub_categories，进入单分类页后以 chips 呈现，点选过滤 c= |
| 官方标签墙 | `/categories` 的 blocks：4 组 43 个官方标签。点标签 = main_tag=3 的标签流。这是禁漫内容发现强于哔咔的地方，给一级入口 |
| 完结筛选 | 不出现。/album 无 status 字段，supportsStatusFilter=false |

### 5.3 搜索

| 项 | 设计 |
|---|---|
| 维度 Tab | 综合(main_tag=0) / 作品(1) / 作者(2) / 角色(4，隐藏——实测无独立价值则不露) / 标签(3)。四维各有独立结果与真实 total（实测「姐姐」全站 80 / 韓漫 34 / 作者维度 18 / 标签维度 1695） |
| 分类过滤 | c= 透传（实测生效），chips 形式 |
| 排序 | 同首页 3 项 |
| 筛选项不出现清单 | 汉化组 / 上传者 / 完结状态 / 时间范围——移动端无对应参数 |
| 作者/标签入口 | 详情页作者名点 → 作者维度搜索；标签 chip 点 → 标签维度搜索。**打通详情 → 搜索的闭环**（PiKA 中禁漫下该入口被硬编码隐藏，本 App 直接具备） |
| 车号直达 | 搜索纯数字关键词时优先按 album id 直达详情（参考社区库 redirect_aid 行为），失败回退关键词搜索 |
| 热搜词 | 不做。无热词端点；/categories/filter 的 tags:[3] 是轮换位不是热词 |

### 5.4 漫画详情

| 项 | 设计 |
|---|---|
| 数据 | `/album?id=`；标题 / 封面 / 作者 / 描述 / 标签 / 作品(works) / 演员(actors) / 观看数 / 点赞数 / 评论数 / 日期 |
| 多作者 | `author` 是数组（多人协作常见），展示与检索均用 ` / ` 连接 |
| 章节 | series[] 按 sort 字段排序（不是数组下标）；空名回退「第 N 话」；单章本子 series 为空 → 章节即本子自身。章节多时折叠 + 「全部 N 话」展开 |
| 相关推荐 | related_list（约 12 条），带封面 |
| 收藏态 | 初值取列表/详情自带的 is_favorite/liked 字段（读侧，无需登录写权限），修掉 PiKA「已收藏显示未收藏、要点两次」的问题 |
| 付费本 | price 非空 → 详情页提示「该作品需在禁漫 App 内获取」，阅读按钮仍可进入可看部分（沿用实测 purchased/price 字段） |
| 想要/点赞 | 不做（无写端点实测依据） |

### 5.5 阅读器（核心体验）

| 项 | 设计 |
|---|---|
| 模式 | 双模式沿用 PiKA：滚动长条（Webtoon 长图切片优化）/ 横滑翻页；双击缩放；预取前后 2 页；上一话 / 下一话 |
| **图片乱序自动还原** | 部分页被服务端「十等分倒序」打乱且**逐图分布**（同章内第 2 页乱、第 3~5 页正常，实测 photo 800000）。阅读器对每张图自动做接缝判定，命中的静默还原（十等分倒序重排）。用户无感；判定结果按（photoId+文件名）缓存，二次进入零开销 |
| 手动兜底 | 阅读器菜单提供「本页横条倒序」开关（默认关）。万一自动判定漏判，用户可手动翻转（自动判定以 56 页实测双门阈值为准：costRev×2 < costIdent 且 costIdent≥20 才还原，避免误翻） |
| 进度 | 本地进度 `{order}:{pageIndex}`，退出即存；已读整本标「读完」；进度归属漫画 id，单源无串源问题 |
| 加载失败 | 单页重试按钮；换图片 host 重试 |
| 预取 | 下载侧同用一套「还原后字节」，预取与离线渲染完全一致 |

### 5.6 本地书架 / 历史 / 下载（未登录也有完整价值）

| 功能 | 设计 |
|---|---|
| 本地书架 bookmarks | 本地收藏漫画（封面、标题、更新时间；支持长按删除、拖拽排序 P1）。**不依赖账号**，是本 App 收藏的主形态 |
| 最近阅读 | 最多 12 条（PiKA 为 6 条，本地主形态下放宽），卡片带「续读 · 第 N 话 P 页」 |
| 已读/读完 | 沿用 ReaderStatus 全量预热机制；卡片角标、列表过滤（看过/没看过） |
| 下载 | 章节级下载（并发 2），manifest.json 原子写；目录 `downloads/{albumId}/{order}/`；文件按魔数定扩展名（实际是 webp，不再硬编码 page_N.jpg）；**存还原后的字节**，离线阅读与在线一致 |
| 云端历史 vs 本地 | 云端历史（/watch_list）登录且验证后才出现；本地历史始终在，两者不合并展示 |

### 5.7 评论（只读先行）

| 项 | 设计 |
|---|---|
| 数据 | `/forum?mode=all&page&aid=`；主键 CID（不是 id）；子评论内嵌 replys + parent_CID，**无需新端点** |
| 治理（尺度=裁决 7 方案 A） | ① content 是 HTML → 剥标签渲染纯文本；② spoiler=1 → 折叠「包含剧透，点击展开」；③ 含外链/网盘/破解导流关键词的条目 → 灰显折叠「疑似广告」；不做内容审查，只做形态治理 |
| 用户卡 | 头像 + 昵称 + 等级徽章（expinfo 对象：level_name/level/badges，数据完整，照 PiKA 哔咔等级条渲染） |
| 发评论 / 回复 | **P2，登录且实测验证后放开**。参数与风控未验证前，输入入口不渲染（不是灰置，是不出现） |

### 5.8 排行榜 / 每周必看

| 功能 | 设计 |
|---|---|
| 排行 | 日(mv_t) / 周(mv_w) / 月(mv_m) 三档，total 真实（143/812/3328），显示「共 N 部」 |
| 每周必看 | `/week` 期数列表（257 期）→ 某期内容流。PiKA 已实现解码但无入口，本 App 作为首页一级入口（白捡的内容位） |

### 5.9 账号侧

| 项 | 设计 |
|---|---|
| 登录 | 用户名 + 密码 → POST /login → data.s → Cookie AVS。登录页说明文案明确「登录仅为解锁云端收藏 / 签到 / 历史 / 评论，浏览与阅读无需登录」 |
| 凭据保存 | AndroidKeyStore AES-256-GCM 加密存（沿用 PiKA SecureAccountStore），支持静默重登 |
| 未登录的「我的」 | 本地书架 / 最近阅读 / 下载 / 已读 / 设置 全部可用；云端区块整体不渲染（不是灰置） |
| 登出 | 清会话；可选删除已存凭据 |
| 不做 | 注册 / 忘记密码 / 改资料 / 改头像 / 改称号（移动端无端点，实测 Not legal） |

### 5.10 设置

| 分组 | 项 |
|---|---|
| 网络 | API 域名（默认「自动」= 内置镜像 + 失败自动换 + /setting 下发；可手填覆盖）；显示当前生效域名 |
| 阅读 | 默认阅读模式（滚动/翻页）、滚动时隐藏底栏、亮度 |
| 通用 | 网格列数（2/3）、分类排序、清除缓存、日志 |
| 关于 | 版本、更新检查（GitHub update.json）、18+ 声明、免责声明 |

## 6. 关键体验规则（跨页面）

1. **「消失」优于「报错」**：本源不支持的每一项（随机、时间筛选、完结、汉化组筛选、注册、改资料…）一律不渲染入口。验收口径：**未支持功能 = 看不见，而不是点了报错**。
2. **乱序还原无感**：用户全程不知道 scramble 存在；仅当手动开关被使用时才在菜单里见到它。
3. **翻页有底**：浏览流 125 页硬上限自动停止；搜索/榜单用真实 total 算页数；页内+跨页按漫画 id 去重（深页码存在轻微重叠，实测）。
4. **域名自愈无感**：接口失败自动换镜像重试；顶部只在「所有线路都失败」时出现错误条。
5. **未登录 ≠ 残缺**：未登录时首页 / 分类 / 搜索 / 详情 / 阅读 / 评论只读 / 下载全部可用。
6. **付费透明**：命中 price 非空即提示来源限制，不静默给空白页。

## 7. 版本规划

### v0.1 · M0–M2「能看」（约 3 天）
- 工程脚手架（fork PiKA 剥离多源）

- 图片乱序自动判定与还原（阅读器 + 下载一致性 + Coil 缓存 key）

### v0.2 · M3–M4「好用」（约 3 天）
- 阅读器完整移植（滚动/翻页/切片/预取/续读）
