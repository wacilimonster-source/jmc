## 1. 本轮交付

| 交付 | 范围 | 说明 |
|---|---|---|
| 系统级闪屏 | `themes.xml` / `colors.xml` / Manifest / `MainActivity` | `androidx.core:core-splashscreen`（兼容 API 26-35）：品牌深紫底 `#211A26` + 应用图标，`postSplashScreenTheme` 退场切回 `Theme.JMRead`；冷启动到 Compose 首帧前不再是纯白窗口（对标 pika perf-arch P0-3/P1-10） |

**已核对无需改造的项**（与 pika 清单逐项对照）：
- manifest.json 写合并（pika P2）：JM DownloadManager 已是「原子 tmp+rename + 单写者通道合并」，不欠账。
- onTrimMemory 清图片缓存（pika P2-7）：JmApp 已实现。
- 启动路径治理（pika P1-10）：JmApp.onCreate 已按 PerfTrace 分段 + 预热后台化，无主线程 runBlocking 关键路径（SourcePrefs/ReaderPrefs 兜底 runBlocking 仅在预热失败时可达，且已有热路径状态位兜底；改造收益<风险，记录不动）。
- DataStore 流 stateIn 化：评估后仍不做（重构面大），记录为后续。

## 3. 过程中发现并修复的问题

1. `ReaderViewModel` 已有 companion object（FLING_PAUSE_MS），新增常量必须并入既有 companion（第二 companion 编译期即红，已合并）。
2. `installSplashScreen` 是 companion 扩展函数，必须 import 后直接调用（全限定调用编译不过）。

## 4. 边界与已知约束

- 冷启动计时量化（am start -W / macrobenchmark）不在本轮（无 adb shell 通道；量化基建留 R10 评估）。
- 写放大收益为代码级论证：非 final 路径写频 1/s → ≤0.25/s，每次写为整份 JSON 重写；最终一致性由 final 直写保证。
